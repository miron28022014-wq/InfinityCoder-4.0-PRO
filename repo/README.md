# InfinityCoder 4.0

**Автономный агентный IDE с полной интеграцией Infinity Ecosystem.**

InfinityCoder 4.0 — это не пересборка «на глаз», а доработка исходников **InfinityCoder 3.0**
(Tauri + React + Vite + Tailwind + CodeMirror) с подключением к ядру экосистемы Infinity:
Core API, AI Runtime, Tool Runtime, Search, Data Services, Memory, Sync и Infinity ID.

Две вещи, ради которых всё затевалось:

1. **Интерфейс.** Переработанная визуальная система: глубокая тёмная палитра с реальной
   глубиной, рельса действий слева, стартовый экран, переработанные чат, композер и карточки
   инструментов, полноценная светлая тема.
2. **Автономность.** Агент доводит задачу сам: не бросает её на полпути, сам возвращается к
   незакрытой работе, не переспрашивает на безопасных операциях, проверяет и чинит результат.

## Что нового в 4.0

### Интерфейс (полный редизайн визуального слоя)

| Что | Как |
|---|---|
| Палитра | Новые токены: глубокий сине-графитовый canvas, приподнятые поверхности, стеклянные панели, акцент-градиент синий→фиолетовый, единая светлая тема |
| Рельса действий | Навигация ушла из вкладок в вертикальную рельсу (Файлы / Агенты / Память / Экосистема) с активным индикатором и бейджами |
| Стартовый экран | Вместо пустого редактора — hero-экран с возможностями, тремя главными действиями и понятным объяснением |
| Панель агента | Новая шапка со статусом и переключателем автономности, переработанные сообщения, карточки инструментов с цветовой семантикой по статусу |
| Композер | «Командная строка» вместо обычного поля: режим, усилие, роль, быстрые подсказки, тумблеры плана/проверки/памяти/автономности |
| Проводник | Корень проекта раскрывается сразу, заголовок панели показывает активный раздел |
| Пустые состояния | Единый крупный компонент с градиентной иконкой вместо мелких серых плашек |

### Автономность (новая механика движка)

* **Продолжение вместо остановки.** Если агент закончил ход финальным текстом, но задача
  выглядит незакрытой (в тексте маркеры «не удалось», «осталось», «продолжу»…), или он вовсе
  не тронул инструменты — движок подталкивает его продолжить. Число подталкиваний
  настраивается (`0…3`, по умолчанию 2).
* **Меньше лишних вопросов.** В автономном режиме политика «спрашивать перед каждым
  действием» понижается до «только опасные операции». Разрушительные операции и `deny`-гранты
  экосистемы по-прежнему требуют вашего решения — это осознанный компромисс.
* **Проверка и починка.** Проверка ответа вторым проходом модели и повторная работа при провале
  проверки (было в 3.0, сохранено и теперь заметно в интерфейсе).
* **Переключатель в двух местах** — в шапке панели агента и в композере, плюс отдельный раздел
  «Автономность» в настройках.

### Интеграция с Infinity Ecosystem

* Клиент Core API: Identity, модели/провайдеры, completions (SSE), гранты, поиск по данным
  экосистемы, объекты, память, Sync, диагностика.
* Транспорт генерации через AI Runtime ядра: **ключи провайдеров остаются на сервере**, в IDE
  попадает только идентификатор модели.
* Локальный режим блокирует облако **на маршрутизаторе**, а не в интерфейсе.
* Гранты экосистемы мапятся на инструменты IDE: `deny` — отказ, `allow` — без подтверждения,
  `ask` — локальная политика.
* Общая память экосистемы подмешивается в контекст; факты из проекта пишутся в общую память.
* Новый инструмент `ecosystem_search`, `ecosystem_remember`, `ecosystem_object`.
* Веб-клиент Core API и его модуль `coder/` — в составе дистрибутива (папка `ecosystem/`).

## Установка

### Linux / macOS

```bash
tar -xzf InfinityCoder-4.0.zip
cd InfinityCoder-4.0
./scripts/install.sh
```

### Windows

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1
```

Установщик:

1. проверяет Node.js ≥ 22.5;
2. разворачивает файлы в `~/InfinityCoder` (`%LOCALAPPDATA%\InfinityCoder`);
3. ставит зависимости и собирает веб-IDE и Core API;
4. создаёт `.env` с новым мастер-ключом и путями к данным;
5. применяет миграции БД экосистемы;
6. регистрирует службы (`systemd --user` / службы Windows) либо печатает команды ручного запуска.

Полезные флаги:

```bash
./scripts/install.sh --dir /opt/ic     # другой каталог
./scripts/install.sh --no-service      # без systemd
./scripts/install.sh --uninstall       # удалить (данные сохраняются)
```

### Ручной запуск

```bash
./scripts/start.sh        # Core API + мост + веб-IDE
./scripts/start.sh core   # только Core API
./scripts/stop.sh
```

* Веб-IDE — <http://127.0.0.1:8090>
* Core API — <http://127.0.0.1:8787>
* Терминальный мост — <http://127.0.0.1:5299>

### Разработка

```bash
npm install
npm run dev          # Vite на :5173, /api проксируется на мост
npm run bridge       # терминальный мост на :5299
npm run check        # tsc + тесты + сборка
npm run screenshots  # скриншоты реального интерфейса (Puppeteer)
```

## Десктопная сборка (Tauri)

Исходники Rust-бэкенда 3.0 на месте и продолжают работать: локальная ФС, терминал, git и
Ledger — всё это по-прежнему делает Rust, а не браузер.

```bash
npm run tauri:build
```

**Ограничение сборки в этом окружении:** здесь нет Rust-инструментов (`cargo`/`rustc`), поэтому
`.msi`/NSIS-пакет в этой сборке не собирался и не проверялся. Проверенный путь — веб-режим с
sidecar-ядром; десктопная сборка воспроизводится на машине с Rust по той же команде.

## Архитектура

```
InfinityCoder 4.0
├── src/
│   ├── lib/
│   │   ├── ipc.ts            слой доступа: Tauri ↔ браузерный VFS
│   │   ├── engine.ts         ReAct-цикл, автономность, рой, проверка
│   │   ├── ecosystem.ts      клиент Core API
│   │   ├── ecosystem-llm.ts  транспорт генерации через ядро
│   │   ├── tools.ts          27 инструментов (24 локальных + 3 экосистемных)
│   │   ├── agents.ts         роли и их права
│   │   └── prompts.ts        системные промпты
│   ├── components/
│   │   ├── shell/            TitleBar, ActivityRail, StartScreen
│   │   ├── chat/             ChatPanel, Composer, MessageItem, ToolCard
│   │   ├── explorer/         Проводник, роли, память
│   │   ├── ecosystem/        Панель экосистемы
│   │   └── settings/         Настройки (в т.ч. «Автономность»)
│   └── index.css             дизайн-система
├── ecosystem/                Core API экосистемы (sidecar)
│   ├── src/                  исходники ядра
│   └── dist/                 собранный сервер
├── scripts/                  install, start, stop, bridge, serve-dist, screenshots
└── test/                     parse.test.mts, ecosystem.test.mts
```

**Кто что решает.** Политика — на сервере: выбор модели, секреты провайдеров, блокировка
облака в локальном режиме и права на инструменты решает Core API. IDE отвечает только за
удобство, локальные файлы и выполнение.

## Проверка

```bash
npm test
```

* `test/parse.test.mts` — разбор ответов модели, вызовы инструментов, план.
* `test/ecosystem.test.mts` — клиент Core API на моке: вход, модели, SSE-поток, блокировка
  облака в локальном режиме, гранты, поиск, объекты, память, Sync, диагностика, отказ без токена.

Тип-чекинг: `npm run typecheck` (ошибок нет). Сборка: `npm run build` (ошибок нет).
Скриншоты интерфейса: `npm run screenshots` → `screenshots/`.
