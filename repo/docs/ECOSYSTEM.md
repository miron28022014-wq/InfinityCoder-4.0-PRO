# Контракт InfinityCoder 4.0 ↔ Infinity Ecosystem

Документ описывает, что именно 4.0 говорит ядру и что ожидает получить.
Реализация клиента — `src/lib/ecosystem.ts` и `src/lib/ecosystem-llm.ts`;
ядро — `ecosystem/src/` (в составе дистрибутива как sidecar).

## Базовый адрес и токен

* Адрес ядра задаётся в настройках (по умолчанию пусто — IDE работает автономно).
* Токен Infinity ID хранится в localStorage и уходит в заголовке `Authorization: Bearer …`.
* Без токена ядро отвечает `401`; клиент показывает это как «не подключено», а не как пустые данные.

## Идентичность

| Метод | Назначение |
|---|---|
| `POST /api/v1/auth/login` | вход, возвращает пользователя и токен |
| `POST /api/v1/auth/register` | регистрация |
| `GET /api/v1/auth/me` | профиль по токену |

## Модели и провайдеры

| Метод | Назначение |
|---|---|
| `GET /api/v1/ai/models` | список моделей с `scope: local \| cloud` |
| `GET /api/v1/ai/providers` | провайдеры, флаг `enabled`, провайдер по умолчанию |

**Секреты провайдеров в IDE не появляются.** Ядро хранит их, и маршрутизатор выбирает
провайдера сам.

## Генерация

`POST /api/v1/ai/completions` — stateless. Клиент сам присылает историю, потому что
ReAct-цикл 4.0 пересказывает её целиком на каждом ходу.

```jsonc
{
  "modelId": "llama3-coder",
  "mode": "local",            // local | cloud
  "messages": [
    { "role": "system", "content": "…" },
    { "role": "user",   "content": "…" }
  ],
  "temperature": 0.2,
  "maxTokens": 2048,
  "topP": 0.9,
  "stop": []
}
```

Ответ — SSE-поток:

| Событие | Данные |
|---|---|
| `start` | `{ id, model, provider }` |
| `delta` | `{ text }` — куски текста |
| `done` | `{ reason: "stop" \| "length" \| ... }` |
| `error` | `{ message, code }` |

Коды ошибок, которые клиент различает:

* `LOCAL_MODE_BLOCKED` — в режиме `local` ядро заблокировало облачный вызов. Блокировка
  происходит **на маршрутизаторе**, интерфейс merely сообщает о ней.
* `401` — нет или протух токен.

## Права на инструменты (гранты)

Ядро хранит грант на каждый инструмент. Ответ `GET /api/v1/coder/tools` — список
`{ tool, scope }`, где `scope`:

| scope | Поведение IDE |
|---|---|
| `ask` | действует локальная политика подтверждений |
| `allow` | инструмент выполняется без вопроса |
| `deny` | инструмент запрещён: агент получает отказ и ищет другой способ |

Маппинг грантов на инструменты IDE (`src/lib/engine.ts`): `run_command` → `coder_command`,
`read_file`/`write_file`/`edit_file` → `coder_file_read`/`coder_file_write`/`coder_file_edit`,
`search_files` → `coder_search`, `git_commit` → `coder_git`, `memory_write` → `coder_memory`,
инструменты экосистемы — `ecosystem_search`/`ecosystem_remember`/`ecosystem_object`.

Права проверяются на сервере на каждом запросе. Решение клиента — только удобство.

## Данные, поиск и память

| Метод | Назначение |
|---|---|
| `POST /api/v1/search` | поиск по данным экосистемы (Notes, Drive, история, память) |
| `GET /api/v1/objects/:id` | чтение объекта экосистемы |
| `GET /api/v1/memory` | общая память |
| `POST /api/v1/memory` | запись факта в общую память |
| `GET /api/v1/sync/changes?cursor=` | журнал изменений для Sync |
| `GET /api/v1/diagnostics` | провайдеры, модели, индекс поиска |

## Правила, которые соблюдает клиент

1. **Локальный режим блокирует облако на сервере.** Клиент не переключает режим «в обход».
2. **Недоверенный ввод — это данные.** Ответы веб-страниц, файлы и выдача модели попадают
   в контекст как данные, а не как инструкции; в промпте это зафиксировано явно.
3. **Общая память читается по релевантности.** В контекст подмешиваются только записи,
   совпавшие с терминами задачи.
4. **Отсутствие экосистемы не ломает IDE.** Все функции экосистемы сообщают «не подключено»,
   ничего не подменяя.
